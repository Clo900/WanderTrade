# 任务系统下一步更新方案（仅规划，不落地代码）

> 更新日期：2026-08-25  
> 本文用于承载“任务限时 + 品质 + 惩罚体系”的代码落地路线拆分；本轮不实现这些内容。  
> 已落地的只有：车厢系统“按钮不锁、执行时容量校验”（见 `Docs/任务系统设计.md` 与代码变更）。

---

## 1. 目标拆分

将任务系统落地拆为 5 个小步，避免一次性大改：

1. **数据结构落地**：任务对象补字段（quality、timerStarted、timeLimitSeconds、deadlineTimestamp、speedSnapshot、rewardGoldBase 等），存档兼容。
2. **T1 计时启动点**：从“接取即开始”改为“离开接取城启动倒计时”，并计算 deadline。
3. **结算梯度**：准时/迟到/严重超时/放弃的金币、素材、声望与罚金。
4. **UI 展示**：已接任务卡倒计时、进度条、状态颜色与结算弹窗。
5. **24h 不良记录惩罚**：计数、滚动窗口、临时减益、稀有权重下调。

---

## 2. 建议新增的配置常量（集中管理）

建议在 `index.html` 或未来模块中集中配置：

- `TASK_QUALITY_MULT`：D/C/B/A/S 倍率
- `TASK_QUALITY_TABLE`：稀有度 → 品质概率表
- `TASK_TIME_CONFIG`：
  - `TIME_BUFFER_SECONDS`
  - `TIME_COMPACT_FUNC`（可为分段表或函数）
  - `LATE_GRACE_SECONDS`
- `TASK_PENALTY_CONFIG`：
  - `LATE_GOLD_RATE = 0.3`
  - `PENALTY_GOLD_RATE = 0.2`
  - `MIN_PENALTY_GOLD = 100`
  - `ABANDON_PENALTY_RATE = 0.1`
  - `MIN_ABANDON_PENALTY = 50`
- `TASK_BAD_RECORD_CONFIG`：
  - `WINDOW_MS = 24h`
  - thresholds：10/20/30
  - debuffs：金币倍率、史诗/传说权重倍率

目的：
- 让策划改数值只改一处
- 避免“散落魔法数”导致文档与代码不一致

## 3. 数据结构与存档兼容

### 3.1 新字段如何补齐

对旧存档：
- `quality`：按稀有度重新 roll（或默认 C）
- `timerStarted`：默认 false
- `deadlineTimestamp/timeLimitSeconds`：若任务已在进行中且玩家不在接取城市，可用“当前时间 + 15 分钟”兜底，并弹一次提示（避免老档直接失败）

### 3.2 服务端存档

当前服务端 `server.ps1` 是“整包 gs 存取”，不做结构校验；因此字段新增主要是客户端兼容问题。

---

## 4. T1 启动点与 deadline 计算

### 4.1 推荐落地点

在旅行出发函数（`startTravel()`）或“从城市离开”路径上：

1. 遍历 `GS.tasks.active`
2. 对 `t.timerStarted===false && t.from===当前城市` 的任务：
   - 计算 `speedSnapshot = getVehicleSpeed()`（里/分钟）
   - 计算 `timeLimitSeconds`、`deadlineTimestamp`
   - 标记 `timerStarted=true`

### 4.2 防口径漂移

任务启动时保存 `speedSnapshot` 与 `timeLimitSeconds`，后续即使换车厢也不回溯修改时限；玩家自行承担“换慢车导致迟到”的风险。

---

## 5. 结算改造点

### 5.1 领取奖励函数

现状 `completeTask(tid)` 实际语义是“领取奖励”。建议：
- 保留函数名但在注释/文档中统一口径（或重命名为 `claimTaskReward`）
- 加入时间判定：准时/迟到/失败分支

### 5.2 迟到规则（已确认）

- 迟到只给 30% 金币
- 声望与素材为 0

### 5.3 严重超时失败

需要支持：
- 自动失败（到点即失败）或“领取时判定失败”
- 失败时扣罚金
- 失败计入不良记录

---

## 6. UI 改造点

### 6.1 已接任务卡片

新增：
- 倒计时（MM:SS）
- 进度条
- 状态文案与颜色（充裕/紧张/已延误/已失败）

### 6.2 结算弹窗

准时：全额展示  
迟到：明确提示“仅 30% 金币，声望/素材取消”  
失败：提示罚金与不良记录计数变化

---

## 7. 24h 不良记录惩罚落地

### 7.1 计数模型

建议在 `GS` 或独立结构中存一组时间戳数组：
- `taskBadLog = {abandonAt:[], failAt:[]}`

每次写入后做一次裁剪：仅保留最近 24h。

### 7.2 惩罚注入点

1. 任务生成（roll rarity）：对史诗/传说权重乘以倍率  
2. 任务结算金币：对最终金币乘以倍率

迟到不计入 badCount（已确认）。

---

## 8. 与车厢系统的协同

本轮已将“车厢锁定”改为“执行时容量校验”。  
后续任务限时落地后，需要补充 UI 解释：
- “任务时限按出发时速度计算（speedSnapshot）”
- 提醒玩家：更换更慢车厢可能导致迟到/失败
