>
> 本文档为**大地图绘制 / 路网配置 / UI 表现 / 与逻辑层关联**的实现索引：精确到文件与行号，梳理函数职责与调用链，供多人协作定位代码、后续模块拆分参考。行号以当前工作区代码为准，改动后请同步更新。

## 1. 架构分层总览

```
┌─ 数据层  src/core/data.js            CITIES（13 城含坐标）/ ROADS（21 条路含里数）/ ITEMS
├─ 逻辑层  src/gameplay/pathing-core.js  buildGraph / shortestPath（最短路径 · 总里数）
│          index.html 主文件             startTravel / advanceDay（旅行结算 · 到达推进）
├─ 表现层  index.html 主文件             renderMap / roadCurve / ptOnRoad / updateTravelUI / 地图交互
├─ 状态层  src/core/state.js            State 容器 + GS 响应式 Proxy（旅行/位置等状态统一入口）
└─ 运行时  src/app/runtime.js + event-bus.js   启动装配 / 事件总线
```

**设计原则**：逻辑与表现**共用同一份 `CITIES/ROADS` 数据**；逻辑只算"走哪些路、多少里"，表现只负责"画成什么形状、点放在哪"。改配置（加城/改路）逻辑与地图自动同步。

## 4. 逻辑层（路线计算 / 旅行结算）

### `src/gameplay/pathing-core.js`（已拆模块）

| 行号 | 函数 | 说明 |
|------|------|------|
| 4 | `buildGraph()` | 由 ROADS 构建邻接表 `{city:{neighbor:里数}}` |
| 5-10 | `shortestPath(from,to)` | Dijkstra 最短路，返回 `{path:[...], distance}` |
| 12-13 | `window.buildGraph/shortestPath` | 全局暴露 |

### 主文件（index.html）

| 行号 | 函数 | 说明 |
|------|------|------|
| 1526-1545 | `startTravel(destId)` | 旅行结算：`shortestPath` 算距离 → `realSec` 耗时、`calcDurabilityLoss` 耐久 → `State.batch` 写入 `vehicle.durability` 与 `traveling{to,startedAt,arrivalTime,routeDistance,pendingEvent}`；**v9.9 起星陨城开放通行（无拦截）** |
| 1214-1243 | `advanceDay()` | 每 tick 推进：旅行到达时 `State.batch` 置 `location=to`、`traveling=null`、`justArrived`（地图/旅行状态唯一变更点） |

> **逻辑 ↔ 表现关联**：`startTravel` 写入的 `traveling`（含 `startedAt/arrivalTime/routeDistance`）是地图蓝点与进度条的**唯一数据源**；到达由 `advanceDay` 统一结算。

## 6. 状态层（GS / State 在地图与旅行中的使用）

`src/core/state.js`：`GS` 是响应式 **Proxy**，顶层写入自动通知；嵌套写入推荐 `State.set(path,val)`；`State.batch(fn)` 批量合并通知。

| 场景 | 写入方式 | 位置 |
|------|----------|------|
| 出发 | `State.batch` 内 `State.set('vehicle',...)` + `State.set('traveling',{...})` | startTravel L1305-1309 |
| 到达 | `State.batch` 内 `State.set('location',to)` / `State.set('traveling',null)` / `State.set('justArrived')` | advanceDay L1031-1040 |
| 存档恢复 | `State.batch` 内逐字段 `State.set`（含 `traveling`） | applySaved L363-397 |
| 重置 | `State.batch` 内 `State.set('traveling',null)` 等 | resetGameState L648+ |

> 地图渲染 `renderMap/updateTravelUI` **只读** `GS.location / GS.traveling`，不直接改状态——状态统一由 `State.set` 写入，便于订阅式 UI 后续接入。

