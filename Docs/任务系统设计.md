# 任务系统设计（vNext：限时 + 品质 + 经济梯度）

> 更新日期：2026-08-25  
> 覆盖范围：城市任务板（送货 / 送客）、任务刷新、限时结算、品质波动、惩罚体系、与倒货（贸易）并行梯度  
> 本文为可执行规格；对应代码已落地（见 `Docs/任务系统下一步更新方案.md` 实施记录）。

---

## 1. 设计目标

- 任务与倒货（贸易）是两条**并行赚钱路线**：  
  - 任务：提供“稳定但受时效约束”的金币来源，并兼顾材料产出（载具升级）  
  - 倒货：提供“高自由度、高波动、高上限”的利润
- 解决三个核心问题：  
  - 任务可囤积、可慢慢挑选，导致“稳定刷金压制倒货”  
  - 高收益任务缺少对应风险（时间成本/失败成本）  
  - 高级任务之间收益缺少波动（导致“固定最优路线”）

---

## 2. 核心机制总览

本版本引入三件事：

1. **现实时间限时（T1）**：倒计时在玩家离开接取城市时启动，且对玩家是动态的（取决于出发时的载具速度/配置）。
2. **任务品质（D/C/B/A/S）**：在稀有度之外增加一层“品质倍率”，使高级任务之间存在稳定波动。
3. **惩罚体系**：迟到奖励大幅衰减；放弃与严重超时会计入 24h 不良记录并施加临时减益。

## 3. 数据模型（任务对象字段）

任务对象（`GS.tasks.active[]`）建议新增/补充字段如下：

```js
{
  id,
  type,        // 'deliver' | 'escort'
  capType,     // 'cargo' | 'pass'
  from, to,
  item, qty,

  rarity,      // 'common' | 'rare' | 'epic' | 'legend'
  quality,     // 'D' | 'C' | 'B' | 'A' | 'S'
  urgency,     // 'relax' | 'standard' | 'urgent' | 'rush'（时效档位，v9.4）

  rewardGoldBase,  // 不含品质、时效的基础金币（用于结算解释/回放与罚金基准）
  rewardGold,      // UI 展示用“准时全额金币”（= rewardGoldBase × 品质倍率 × 时效金币加价）
  rewardRep,
  rewardMats,

  delivered,        // 抵达目的地标记（现有）

  // === 限时字段（T1） ===
  timerStarted,     // bool：是否已启动倒计时（首次离开 from 城时置 true）
  speedSnapshot,    // number：启动计时瞬间的“实际时速”（用于说明/防口径漂移）
  timeLimitSeconds, // number：总时限（秒）
  deadlineTimestamp,// number：截止时间戳（ms）
  status            // 'active' | 'late' | 'failed'（可选：渲染用）
}
```

说明：
- `rewardGold` 仍表示“准时全额金币”，便于任务板对比与筛选；结算时再按准时/迟到/失败折算。
- `speedSnapshot` 只用于解释与一致性：即便玩家之后换车厢，时限也不回溯修改（玩家自行承担风险）。
- `urgency` 缺失的旧存档由 `normalizeTask` 补为 `standard`（×1.0，不影响旧档）。

## 4. 任务品质系统

### 4.1 品质倍率（金币）

| 品质 | 倍率 |
|---|---:|
| D | ×0.85 |
| C | ×1.00 |
| B | ×1.15 |
| A | ×1.30 |
| S | ×1.45 |

> 所有稀有度（包括传说）都具备品质波动。

### 4.2 品质分布（默认表 · v9.4 放宽高稀有度低品质通道）

| 稀有度 | D | C | B | A | S |
|---|---:|---:|---:|---:|---:|
| 普通 | 40% | 35% | 15% | 10% | 0% |
| 稀有 | 25% | 30% | 25% | 15% | 5% |
| 史诗 | 10% | 25% | 35% | 20% | 10% |
| 传说 | 5% | 15% | 35% | 30% | 15% |

> 传说 D/C 保留“慢单”通道（高基础收益 × 低品质 × 宽松时限 = 慢工高收益），靠低概率平衡。

## 4A. 时效档位系统（v9.4：独立维度，类似外卖配送时长 + 急单加价）

任务在「稀有度 × 品质」之外再抽取一个**时效档位**，形成完整组合：任务 = 稀有度（基础收益）× 品质（金币倍率）× 时效（时限倍率 + 金币加价）。

### 4A.1 档位定义

| 档位 | 时限倍率 | 金币加价 | 含义 |
|---|---|---:|---:|
| 宽松 relax | ×1.50 | ×0.97 | 配送时间充裕，可顺路挂单（v9.7 金币 0.95→0.97） |
| 标准 standard | ×1.15 | ×1.00 | 常规 |
| 紧急 urgent | ×0.85 | ×1.10 | 时间紧、收益高 |
| 加急 rush | ×0.65 | ×1.20 | 极紧时限、最高收益与风险 |

### 4A.2 抽取概率（v9.7 上调慢单：宽松↑、加急↓，标准仍为主体）

| 稀有度 | 宽松 | 标准 | 紧急 | 加急 |
|---|---:|---:|---:|---:|
| 普通 | 46% | 44% | 9% | 1% |
| 稀有 | 36% | 46% | 15% | 3% |
| 史诗 | 28% | 46% | 21% | 5% |
| 传说 | 22% | 44% | 27% | 7% |

### 4A.3 金币与罚金口径

- `rewardGold = rewardGoldBase × 品质倍率 × 时效金币加价`。
- `rewardGoldBase` 仍 = 稀有度 × 距离（不含品质/时效）——**违约金与放弃罚金基于它**，不被品质/时效放大。

### 4A.4 时效 UI 规格（无图标）

- 时效标签（宽松/标准/紧急/加急，仅文字+颜色）放在任务卡**顶部行（与稀有度/品质同行），向右靠齐**（位于刷新按钮左侧）。
- 时限行显示 `⏱️ 时限：X 分钟`；已接未出发显示 `时限：X 分钟（未出发，不计时）`。
- 任务板顶部图例：`时限倍率：宽松 ×1.5 · 标准 ×1.15 · 紧急 ×0.85 · 加急 ×0.65（按当前时速估算，出发后锁定）`。

## 5. 限时机制（T1：离城启动，动态时限）

### 5.1 倒计时启动规则

- 玩家在城市 `from` 接取任务后，倒计时**不立即开始**。  
- 当玩家**首次离开 `from` 城**（触发旅行出发流程）时：
  1. 记录 `speedSnapshot = 当前实际时速`  
  2. 计算 `timeLimitSeconds` 与 `deadlineTimestamp`  
  3. 置 `timerStarted = true`
- **时间权威（v9.4）**：在线模式以服务器时间为准——`/api/world` 返回 `serverNow`，客户端计算 `clockOffset` 后统一用 `nowMs()`（`Date.now()+clockOffset`）计算/判定时限，防本地改钟作弊；单机模式 offset=0。

### 5.2 时限 UI 文案

- **可接任务卡**（未接取）：描述下一行显示 `⏱️ 时限：X 分钟`（按当前实际时速估算，不写“约”）。
- **已接任务卡·未出发**：显示 `时限：X 分钟（未出发，不计时）`。
- **已接任务卡·已出发**：实时倒计时与进度条（🟢 充裕 / 🟡 适中 / 🟠 即将到期 / 🔴 紧急 / ⚠️ 已延误 / ❌ 已失效）。

### 5.3 时限计算公式（可调参）

定义：
- `distance`：最短路径里数
- `speed`：玩家出发时实际时速（里/分钟），取 `speedSnapshot`
- `baseSeconds = distance / speed * 60`
- `urgencyMult`：时效档位时限倍率（宽松 1.5 / 标准 1.15 / 紧急 0.85 / 加急 0.65）

推荐默认参数：
- `TIME_BUFFER_SECONDS = 120`（固定缓冲，用于装卸/操作；**不随时效缩放**）
- `TIME_COMPACT_FACTOR`：**距离中性，恒定 1.08**（v9.4 起不再随距离变紧/变宽；时限差异主要由时效档位决定，避免远距任务被卡得过紧）

最终：

```
timeLimitSeconds = baseSeconds × 1.08 × urgencyMult + TIME_BUFFER_SECONDS
deadlineTimestamp = serverNowOrDateNow + timeLimitSeconds*1000
```

> 在线模式推荐以服务器时间戳为准（仅用于防作弊；本项目当前版本不做离线收益）。

## 6. 结算梯度（准时 / 迟到 / 严重超时）

### 6.1 判定窗口

- `LATE_GRACE_SECONDS = 300`（5 分钟）

### 6.2 准时（100%）

触发：`now <= deadlineTimestamp`

- 金币：100%（含品质倍率的全额）  
- 声望：100%  
- 素材：正常判定

### 6.3 迟到（仅 30% 金币）

触发：`deadlineTimestamp < now <= deadlineTimestamp + LATE_GRACE_SECONDS*1000`

- 金币：30%（向下取整）  
- 声望：0  
- 素材：0

### 6.4 严重超时（失败 + 罚金）

触发：`now > deadlineTimestamp + LATE_GRACE_SECONDS*1000`

- 任务失败：任务从 active 移除，容量立即释放
- 罚金：`penaltyGold = max(rewardGoldBase * PENALTY_GOLD_RATE, MIN_PENALTY_GOLD)`
  - 默认：`PENALTY_GOLD_RATE = 0.2`，`MIN_PENALTY_GOLD = 100`
- 声望惩罚：本版本不扣声望（仅扣钱）
- 计入 24h 不良记录（见 §7）
- **自动失败（v9.4）**：每秒 tick 调用 `settleOverdueTasks()`，到点即自动结算（不再依赖"领取时判定"）；在线 `fullSync` 上线时结算离线期间超时任务，多个任务汇总一次提示。

## 7. 放弃任务与 24h 不良记录惩罚

### 7.1 放弃罚金

- 放弃罚金：`abandonPenalty = max(rewardGoldBase * 0.1, 50)`  
- 扣除金币不足则扣到 0，不产生负债  
- 放弃计入 24h 不良记录

### 7.2 不良记录计数（滚动 24 小时）

仅统计：
- 放弃次数 `abandonCount24h`
- 严重超时次数 `failCount24h`

`badCount24h = abandonCount24h + failCount24h`

不统计：
- 迟到交付（不计入 badCount24h）

### 7.3 临时惩罚（建议默认）

触发阈值：`10 / 20 / 30`

| badCount24h | 任务金币倍率 | 史诗/传说刷新权重倍率 |
|---:|---:|---:|
| ≥10 | ×0.95 | ×0.9 |
| ≥20 | ×0.85 | ×0.7 |
| ≥30 | ×0.70 | ×0.4 |

说明：
- “刷新权重倍率”只影响 **史诗/传说** 的出现概率，用于抑制“刷高价值任务又频繁毁约”的行为。
- 付费刷新不提高稀有概率（见 §8），因此该惩罚不会被付费绕开。

### 7.4 违约反馈与显示

- **放弃/超时失败后**：toast 显示违约金、`24h 违约记录 N 次`；若已触发减益，追加显示 `任务金币×X · 史诗/传说刷新×X`。
- **任务板顶部**：存在违约记录时显示提示条——
  - 未达阈值：`📋 24h 违约记录 N 次（放弃/超时；累计达 10/20/30 时任务收益下降、高级任务刷新率降低）`
  - 已触发减益：`⚠️ 24h 违约记录 N 次：任务金币 ×X · 史诗/传说刷新权重 ×X`（红色警示）

## 8. 任务刷新规则（只改次数/成本，不改概率）

- 刷新目的：让玩家筛选想做的任务，不提供“抽稀有”的捷径  
- 成本规则沿用现有实现：  
  - 每任务位每城免费 2 次  
  - 第 3 次起：`1000 * 2^(n-2)`（逐次翻倍）  
- 付费刷新不影响：稀有度分布、品质分布、素材概率

## 9. 与倒货（贸易）的经济并行关系

任务线的收益结构：
- “准时”可接近或略高于同路线倒货的中位收益，但**强依赖准时率**；迟到收益被打回到“接近倒货”甚至更低。
- 高收益任务具备高风险：远距更紧（§5.2），对动力车厢/核心强化形成明确需求。

倒货线的收益结构：
- 收益受价格波动、库存、税率与事件影响；上限高但波动大。

互补点（设计意图）：
- 玩家用任务获得稳定现金流与材料，用倒货追求高利润；两者都能独立赚钱，但不应出现单一最优。

任务板 UI 补充：可接任务卡在描述下一行显示“时限：X 分钟”（按当前时速+时效倍率估算）；时效标签（无图标）与稀有度/品质同行、向右靠齐；城市内 5 个可接任务均分横向空间（不滚动）。

### 10.2 车厢系统（关联改动）

车厢操作改为“按钮不锁、执行时容量校验”：
- 更换/卸载按钮始终可点  
- 玩家确认操作时，用 `fitAfterSlot` 预测操作后容量；若会导致【玩家货物+旅客+任务占用】超出容量，则拒绝并弹窗提示
