> 版本：v1.0　|　核对日期：2026-09-09　|　依据代码版本：v9.14.6.5（代码为准，文档仅记录现状）
>
> 覆盖范围：公共事件（全局城市事件系统，44 条）与私人事件（旅行途中，6 种）的机制、字段规范、现状总览、配置方法与联动规则。
>
> 配套文件：`Docs/事件系统配置模板.xlsx`（可直接填写的公共事件/私人事件模板，含全部现状参考行）。

## 1. 系统全景

事件系统分为两套相互独立的机制：**公共事件**改变全服共享的物价与费用，**私人事件**只影响单个玩家的某次旅程。两者都是"确定性种子驱动、无状态存储"的设计，任意时刻查询同一输入得到同一结果，服务器与客户端共用同一套时间轴推算。

| 维度 | 公共事件 | 私人事件 |
|------|----------|----------|
| 影响范围 | 全王国 / 某城 / 某城某物资 / 维修费 | 单个玩家的一次旅行 |
| 触发时机 | 按中枢周期（2 现实小时）确定性判定 | 出发时按路程确定性判定 |
| 结算时机 | 周期内持续生效，价格即时注入 | 抵达时弹窗结算 |
| 当前数量 | 44 条（13 全局 / 31 城市） | 6 种（合计触发率 30%） |
| 配置位置 | `events.js` 的 `EVENT_TABLE` 数组 | `index.html` 内 `rollPrivateEvent` / `showPrivateEvent` |
| 配置方式 | 数组追加一条配置即生效 | 改概率区间 + 结算分支（代码级） |

另有一类"抵达联动"行为在每次进城时自动发生（见 3.4），不构成独立事件，但会影响玩家对事件系统的感知。星陨城活动（`starfallConfig` / `server/starfall.mjs` / `src/gameplay/starfall.js`）与事件系统相互独立，不在本手册范围。

## 2. 公共事件（全局城市事件系统）

### 2.1 时间框架与触发机制

- 游戏日 = 10 现实分钟；中枢周期 = 2 现实小时（= 12 游戏日）。中枢时长随 GM `timescale` 缩放。
- 每个中枢周期对每条事件独立做一次确定性判定：`r = evRnd(evSeed(id, hub))`，`r < freq` 即触发，之后持续 `hubs` 个中枢周期。
- 查询当前事件时回溯最近 6 个中枢（`EVENT_MAX_HUBS = 6`，覆盖最长持续 4 周期加缓冲）。
- 事件开始前 5 分钟进入"预告窗口"（`UPCOMING_WINDOW`），结束前 2 分钟显示"即将结束"（`ENDING_WINDOW`）。

### 2.2 字段规范（公共事件）

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| `id` | 是 | string | 唯一标识（英文小写），用于种子与日志 |
| `name` | 是 | string | 事件显示名（中文） |
| `icon` | 是 | string | 横幅图标（emoji） |
| `scope` | 是 | string | `global` / `city` / `item` / `cost` |
| `items` | global 时必填 | array | 受影响的物资 id 列表（仅 global） |
| `city` | city/item 时必填 | string | 城市 id |
| `item` | 否 | string | 指定物资；**不写 = 该城全部物资** |
| `mult` | 否 | number | 价格乘数（>1 涨，<1 跌） |
| `target` | 否 | string | `buy` / `sell` / `both`（缺省 = both） |
| `spread` | 否 | number | 买卖价差率增量（0.02 = +2%） |
| `repairMul` | 否 | number | 维修费用乘数（仅 scope = cost） |
| `hubs` | 是 | int | 持续中枢周期数（建议 1~4） |
| `freq` | 是 | number | 每周期触发概率（建议 0.04~0.25） |
| `desc` | 是 | string | 效果描述；括号内为内部备注，玩家端自动剥离 |

效果字段 `mult` / `spread` / `repairMul` 至少提供一项，否则事件无实际效果。同类事件同时生效时效果**相乘叠加**。

### 2.3 校验规则与平衡建议

- `scope:'global'` 必须带 `items`；`scope:'city'/'item'` 必须带 `city`。
- `city` 必须与 `map/world-map.json` 中的城市 id 完全一致；`item` 必须与 `src/core/data.js` 的 `ITEMS` 键一致，否则事件永不生效。
- 城市整体事件幅度建议克制（×1.05~1.15），单品事件可更激进（×0.7~1.4）。
- `freq` 过高会频繁刷屏；全局事件建议同时生效不超过 3~5 条。
- 在线交易服务端存在价格比率窗口校验（约基准价 [0.12, 6]），事件幅度叠到窗口外时，成交可能被服务端拦截。
- `EVENT_TABLE.length` 会被"事件见闻录"图鉴与成就 `event_seer` 动态引用：增删事件会自动改变成就目标，无需额外维护。

### 2.5 玩家可见性与情报所联动

- 全局 / cost 事件进行中**始终可见**（不限所在城市）。
- 城市事件：抵达该城自动标记"已知"（`markCityAsKnown`，只标记进行中事件）；离开后已标记的事件保留至过期，该城之后"新发生"的事件需返回该城或经其他城情报所打听才可见。
- 预告事件（开始前 5 分钟窗口）只能通过**情报所打听消息**获得，未获得前任何玩家都看不到。
- 情报所每城独立解锁（代码实际值：解锁 50,000 金、打听 10,000 金/条），本城声望决定情报范围、事件情报概率与单次条数。
- "事件见闻录"记录玩家见证过的所有事件 id（永久收藏，用于成就与图鉴）。

### 2.6 新增公共事件步骤

1. 在 `Online-Client/src/economy/events.js` 的 `EVENT_TABLE` 末尾追加一条：
```js
{id:'spice_boom',name:'香料走俏',icon:'🧂',scope:'city',city:'windoasis',item:'spice',
 target:'buy',mult:1.2,hubs:3,freq:0.12,desc:'风语绿洲香料买入价 ×1.2（商旅热捧，仅买入价）'}
```
2. 对照 2.2 字段与 2.3 校验规则自查（city / item 必须与数据源一致，见第 4 章）。
3. 无需改动引擎与 UI：价格注入、横幅、详情弹窗、预告与见闻录全部自动生效。
4. 若项目使用 `内测开服包-20260902/` 部署，需同步更新该包内的 `src/economy/events.js` 副本。

常用场景配方：

| 想要的效果 | 写法要点 |
|------------|----------|
| 某物资买入价下跌 | `scope:'item', target:'buy', mult:0.8` |
| 某物资卖出价上涨 | `scope:'item', target:'sell', mult:1.3` |
| 某城全部物资上涨 | `scope:'city', city:'xxx'`（不写 item） |
| 全王国某类物资下跌 | `scope:'global', items:[...], mult:0.9` |
| 维修费用打折 | `scope:'cost', repairMul:0.7` |
| 价差拉大（卖出吃亏） | `scope:'city', city:'xxx', spread:0.03` |

## 3. 私人事件（旅行途中）

### 3.1 触发与结算机制

- 出发时在 `startTravel` 内调用 `rollPrivateEvent(路程, 目的地)` 判定；**路程 ≤ 4 里不触发**（新手保护）。
- 判定为确定性种子：`seededRnd(路程×7919 + 游戏日×104729 + 目的城市首字符×31)`。
- 结果缓存于 `GS.traveling.pendingEvent`，抵达时经 `advanceDay` 转入 `GS.pendingEvent`，到达动画后弹出结算弹窗。
- 结算全部使用网页内弹窗（劫匪为双按钮选择），不使用浏览器原生弹窗。

### 3.2 现状（6 种）

概率在代码中以累计区间实现：`r<0.08` rob → `r<0.12` breakdown → `r<0.17` merchant → `r<0.22` repairman → `r<0.26` bump → `r<0.30` buyer，合计 30%。

| type | 事件 | 概率 | 结算效果 |
|------|------|------|----------|
| rob | 路遇劫匪 🏴 | 8% | 有货：损失 10%~30% 货物，双按钮（赎买 = 携带货物估值 20%，允许负债 / 硬抗损失）；无货：抢金币 10%~30%（可为负），金币为 0 则悻悻离去 |
| breakdown | 载具故障 🔧 | 4% | 耐久 −30 |
| merchant | 偶遇行商 🛒 | 5% | 随机一件所载物资按本城卖出价 ×1.15 全量买断 |
| repairman | 偶遇工匠 🔧 | 5% | 下次维修 5 折（`GS.repairDisc=0.5`，维修后清除） |
| bump | 道路颠簸 🪨 | 4% | 耐久 −10 |
| buyer | 货主急购 💰 | 4% | 随机一件所载物资按本城卖出价 ×1.3 全量买断 |

正面（merchant / repairman / buyer = 14%）与负面（rob / breakdown / bump = 16%）大致平衡。收购类只处理玩家自有货物（`GS.cargo`），任务货物不参与。

### 3.3 配置方法（代码级）

私人事件**没有配置表**。调整数值或新增类型均需改 `Online-Client/index.html`（内测包有同路径副本需同步）：

- 只调概率：改 `rollPrivateEvent` 中的累计阈值区间，注意新增区间必须接在现有区间之后。
- 调结算效果 / 文案：改 `showPrivateEvent` 对应分支（数值、扣货、扣金、发事件总线通知）。
- 新增类型：`rollPrivateEvent` 追加区间返回 `{type:'xxx', ...}`，`showPrivateEvent` 追加结算分支；单按钮用 `showModal`、双按钮用 `showChoice`，结算后调 `render()`。
- 事件触发率建议总量 ≤ 30%，并保持正负面大致均衡。

### 3.4 抵达城市时的联动行为

每次进城除结算私人事件外，还会自动执行（与策划文案相关的部分）：

| 行为 | 说明 |
|------|------|
| 标记本城进行中事件为已知 | 使本城事件出现在事件横幅，直到过期 |
| 情报信息栏清空 | 仅保留"已抵达××"系统提示；本城已抽事件去重集合清空 |
| 首次到访记录 | 记入 `visitedCities` 并播放抵达遮罩 |
| 生成任务板任务 | 星陨城除外（该城无任务 / 市场 / 情报所，整页切换为活动面板） |
| 到站任务处理 | 暂停任务倒计时、标记已交付（按真实到达时刻） |

## 5. 已知差异与待确认项（本次仅记录，未改动）

以下差异是核对代码与既有文档时发现的，按你的要求仅作记录，未修改任何文档或代码。生成或改文案时请以代码行为为准。

1. **情报所数值文档滞后**：`Docs/跑商游戏事件系统设计.md` §3c 与 `Docs/CODE_WIKI.md` §6.7 记载"解锁 5,000 / 打听 1,000、事件概率 18%/32%"，代码实际为解锁 50,000 / 打听 10,000、预告 3%~8% / 进行中 5%~12%（随声望）。疑似为货币量级放大与概率平衡改动后文档未同步。
2. **示例城市 id 错误**：事件设计文档 §5.1 与 CODE_WIKI §9.2 的示例使用 `city:'windy_oasis'`，真实 id 为 `windoasis`；照抄示例会配置出永不生效的事件。
3. **desc 描述未实现效果**：`storm`（盐湾港风暴）的 desc 声称"出行耐久损耗 +50%"，但事件字段与逻辑中无对应实现；玩家详情弹窗会看到这条不存在的效果，需要确认文案或补齐实现。
4. **配置碎片化且有部署副本**：公共事件在模块 `events.js`，私人事件与情报所参数在主 `index.html`，同时 `内测开服包-20260902/Online-Client/` 下有独立副本；改动需同步两份文件。私人事件目前只能改代码，无法填表。
