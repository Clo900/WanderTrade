# 地图编辑器「地形功能无法改变地形」检查与修复方案

> 适用范围：`tools/map-editor/`（地形模式）+ `hex-map-lab/src/interaction/`（相机 / 拾取）
> 结论先行：**数据链路没有坏，坏的是交互模型** —— 涂刷只绑定在「单击」上，而左键拖拽被相机旋转占用；沿用旧版「按住左键连续涂刷」的习惯时既不写入覆写、也不给任何反馈。

---

## 一、现象与复现

**现象**：进入「地形模式」，在 3D 预览里刷地形，地形不变。

**最小复现（无头 Chrome，命中率 100%）**：把 `#brushTerrain` 选为「水域」，然后

| 操作 | 覆写格数 | 状态栏 |
| --- | --- | --- |
| 按住左键从左向右拖动（模拟连续涂刷） | **0 → 0** | 仍是「地形预览就绪：557 格」，**毫无变化** |
| 在同一位置改为单击 | **0 → 1** | 「重建完成：557 格 / 覆写 1 格 · 3452ms」 |

即：**拖拽 = 完全无效，且不给任何提示；单击 = 正常生效。** 这与旧版地形刷「按住鼠标左键可连续涂刷」的既有操作习惯直接冲突。

## 二、排除项（数据链路与启动方式都是好的）

为避免误判，先做了三组对照，证明不是「覆写没写进去」或「引擎不认」：

| 对照 | 做法 | 结果 |
| --- | --- | --- |
| 引擎最小探针（纯 Node，不经编辑器） | `HL.World.build({ terrainOverrides: { tiles: { "<key>": … } } })` | `terrain=water` 水格 158→159；`forest` 林 85→86；`ridge` 山 81→82；`landform=hill` 生效 —— **覆写确实改变地块类型** |
| 编辑器：绕过面板直接写模型 + 重建 | `TerrainModel.setEntry(key,{terrain:'forest'})` → 回读世界 | 该格 `grass → forest`，`terrainOverrides.count = 1` |
| 编辑器：完整用户流程（选下拉 → 单击） | 选「水域」+ 刷笔 5 后单击 | 水格 164→217、覆写 61 格、**画面像素哈希变化**、0 运行期错误 |
| 启动方式：`file://` 双击 | 直接打开 `tools/map-editor/index.html` | 引擎装载正常、地形模式挂载 701 格、0 错误（但城市/道路为 0，是空图世界） |

## 三、根因

### 3.1 主因：涂刷只有「单击」一条入口，左键拖拽被相机占用

调用链（三处各司其职，合起来导致拖拽静默失效）：

1. `hex-map-lab/src/interaction/camera-control.js` **L73–L87**：左键按下（未按 Shift）即 `dragMode = 'rotate'`，并 `setPointerCapture`；
2. `hex-map-lab/src/interaction/picker.js` **L98–L101**：抬起时 `if (opts.cameraControl.dragDistance() > 6) return;` —— 拖拽位移超过 6px 就**不触发** `onPickTile`；
3. `tools/map-editor/src/terrain/terrain-view.js` **L79–L88**：`onPickTile` 是**唯一**写覆写的入口；`brush` 没有 `pointermove` 涂刷路径。

结论：只要拖动鼠标（哪怕只为了「刷一片」），位移就 > 6px，于是①相机在旋转、②覆写一个都不写、③没有任何提示。用户看到的就是「地形功能无法改变地形」。

**为什么一定会被撞上**：旧版编辑器（`terrain.hexTiles` 时代）的地形刷是「**按住鼠标左键可连续涂刷**，刷笔按六角距离逐圈扩展」（原文见 `Docs/地图生产与维护.md` 的历史版本）。这次重构把地形搬进 3D，操作改成「单击地块应用」，但只在面板底部留了一行小字提示，**操作习惯被改变而没有被显式告知**。

### 3.2 次因一：静默 no-op

`terrain-view.js` **L113**：未选择任何笔刷字段时

```js
if (!Object.keys(patch).length) { setStatus('请先选择要刷的地形 / 地貌 / 山体 / 水路'); return; }
```

只改一行底部小字（`#terrainStatus`，在 fieldset 底部），既不弹提示也不改变光标，用户几乎必然理解为「没反应」。

### 3.3 次因二：每次生效单击 = 一次 3.1–3.4s 的同步全量重建

`terrain-view.js` **L126–L140** `rebuildNow()` 走的是完整 `WorldRebuild`（含山体 LOD 四级几何）。实测单次 3120–3452ms，**主线程同步冻结**；而 `setStatus('…正在重建…')` 是在阻塞开始**之前**设置的，浏览器通常来不及重绘这行字，因此用户看不到任何进度，只能感觉「点了没反应、界面还卡住」。若此时再点几下，会被 `pendingRebuild` 合并成一次，更强化「点了没用」的印象。

### 3.4 次因三：术语与入口不一致

左栏卡片叫「地形」，面板 fieldset 叫「地形覆写（3D 预览）」，而用户找的是「**地形刷**」；`terrain.hexTiles` 时代那套「地形刷」面板（含 5 类色块图例）已随旧模型删除，没有任何地方告诉用户它去哪了。

### 3.5 边界（不是本次 bug，但会被误判为「没生效」）

`terrain.hex.overrides` 目前**没有运行时消费者**：它只影响编辑器 3D 预览与导出的 `map/world-map.json`。游戏客户端仍按二维等高线 `terrain.features` 绘制地图。因此「改了地形但游戏里看不到」是既有的设计边界，需要在界面上明确写出来，否则用户会把两件事混在一起。

## 四、修改方案

### A. 交互：把涂刷从「单击」扩展为「按住左键拖拽连续涂刷」（核心修复）

**A1（推荐）按键分工：左键＝涂刷，右键/中键/Shift+左键＝相机**

- `hex-map-lab/src/interaction/camera-control.js`
  - `create()` 新增可选参数 `options.rotateButton`（默认 `0`，保持实验页行为不变）；
  - `onPointerDown` 用 `rotateButton` 判定旋转，其余按键（`1`/`2`）继续走平移。
- `tools/map-editor/src/terrain/terrain-view.js`
  - `mount()` 传 `rotateButton: 2`（右键旋转）/ 或让右键与中键都走平移，滚轮缩放不变；
  - **新增涂刷状态机**：`pointerdown`（左键）→ `painting = true`；`pointermove` → 用 `Hex.line(上一格, 当前格)` 补齐快速拖动跨过的格，按 `lastPaintedKey` 去重后逐格 `applyBrush`；`pointerup` → `painting = false` 并触发一次重建。
  - 涂刷期间暂停 `renderFrame` 的相机阻尼更新（避免边刷边转）。
- `tools/map-editor/src/terrain/terrain-preview` 与 `Picker` 的分工：
  - 建议把「涂刷」从 `Picker` 里拆出来，新增 `src/terrain/terrain-brush.js`（自己监听 pointer + 射线拾取），`Picker` 只保留「悬停读数 / 选中地块查看」。这样 `Picker` 不再承担编辑职责，符合既定的功能分区。

**A2（改动最小的折中）**：不动相机，把「单击」放宽为「按住不放、位移 ≤ 6px 的连续点击也可涂」仍然无法覆盖拖拽；因此若不做 A1，至少要让**拖拽时给出「拖拽=旋转视角，涂刷请单击」的显式提示**，并在提示里说明左键用途。这是止血，不是修复。

### B. 反馈：消除静默 no-op 与「卡住」错觉

- `tools/map-editor/src/terrain/terrain-panel.js`
  - 未选择任何笔刷字段时，在预览区顶部（而非底部）显示醒目提示条；
  - 给「地形类型 / 地貌 / 山体 / 水路」加一个「**当前笔刷**」摘要行，让用户随时看到「现在会刷什么」。
- `tools/map-editor/src/terrain/terrain-view.js`
  - `rebuildNow()` 前先 `await nextFrame()`（`requestAnimationFrame`），保证「正在重建…」能真正画出来；
  - 重建期间给 `#sceneHost` 加 `cursor: progress` 与半透明遮罩，结束后移除。

### C. 性能：把「连续涂刷」的反馈压到可用（决定这一步是否好用）

- 涂刷过程中**只写覆写、不重建**（当前已是如此，靠 `pendingRebuild` 合并）；
- 重建时先关山体 / 强制最粗 LOD（山体几何占重建耗时绝大部分），指针抬起并静置 ~200ms 后再做一次完整重建；
- 若后续要做「大范围刷」，再考虑把覆写按区域批量提交。

### D. 文案与文档一致性

- `Docs/地图生产与维护.md`：把地形模式一节改为「**按住左键连续涂刷**（沿轨迹补格）+ 单击单格」，并写明相机按键分工；
- 面板提示、左栏卡片名统一为「**地形刷**」。

### E. 明确边界（界面文案）

- 在 `地形覆写` fieldset 内加一行常驻说明：「覆写只作用于编辑器预览与导出的 `terrain.hex.overrides`；游戏仍按二维等高线绘制」。
- 若要让游戏真正消费地形覆写，另立一项（客户端/服务端读 `terrain.hex`，或改用 hex-map-lab 的 3D 地图）。

## 附录：同轮修复的另外两项

### A. 地形涂刷「鼠标指的位置与实际地块不符」

**根因（结构性）**：`hex-map-lab/src/render/scene.js` 用 `renderer.setSize(w, h, false)` —— 第三个参数 `false` 表示**不写 canvas 的 CSS 尺寸**，嵌入方必须自己给。编辑器 CSS 只写了 `#sceneHost canvas { display: block }`，于是 canvas 的 CSS 尺寸退化为它的**内在像素尺寸** `w×dpr × h×dpr`：

- 在 `devicePixelRatio > 1` 的机器上（Windows 125% / 150% 显示缩放），canvas 比容器大、右下部分被容器裁掉，用户看到的只是整帧的左上角；
- 而 `Picker` / `pickTileAt` 仍按**容器矩形**换算 NDC ⇒ 拾取位置与画面错位，**偏差随离左上角的距离线性放大**。

**为什么此前没被发现**：实验页 `styles.css` 第 45 行有 `#canvas-host canvas { width:100%; height:100% }`（所以实验页正常），编辑器漏了这两行；而所有无头测试都在 `deviceScaleFactor = 1` 下跑，DPR=1 时 canvas 尺寸恰好等于容器，两个坐标系重合，于是漏检。

**修复**：`tools/map-editor/styles/editor.css` —— `#sceneHost` 补 `touch-action: none`，canvas 补 `width/height: 100%`，并在注释里写明原因。

**回归**：新增 `tools/map-editor/tests/canvas-pick-alignment.regression.js`（**必须 DPR=1.5**）。断言：canvas 显示尺寸/位置 == 容器；背板 = 容器 × DPR；把 30 个地块格心投影到屏幕后用 `TerrainView.pickAt`（= 涂刷实际走的那条路径）拾取必须命中自身 —— 低透视 30/30、正交 30/30。

### B. 相机默认改为「低透视」，正交由按钮切换

- `hex-map-lab/src/render/scene.js`：新增常量 `DEFAULT_MODE = 'perspective'` 并作为装配默认值，同时在 `sceneKit` 上暴露 `defaultMode`（供 UI 初始化按钮，避免与装配默认值漂移）。`applyRig` 本就用 `ortho.zoom` 把正交对齐到「同一距离下的可见高度」，所以两种模式**取景范围一致、切换不改缩放**。
- `hex-map-lab/src/app/hud.js`：默认高亮改为「低透视（主）」，另一个按钮改为「正射」。
- 编辑器：地形面板新增**「视角」按钮**（低透视 ⇄ 正交）；`TerrainView.setCameraMode()` / `cameraMode`；切换后调用 `picker.invalidate()`（投影矩阵变了，悬停缓存必须丢）。
- 文档措辞同步：`Docs/地图生产与维护.md`、`hex-map-lab/README.md`（README 里「正交是默认档」「默认视角（正交…）」等表述已更正）。
